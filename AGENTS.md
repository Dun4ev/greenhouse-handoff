# Greenhouse: инструкции проекта

## Архитектура фронтенда

- Экраны работают через единый контракт данных. Не вызывай API напрямую из UI и не подключай оборудование из браузера.
- Тестовый и реальный адаптеры должны быть взаимозаменяемы. Выбирай адаптер в одной точке сборки приложения; не меняй компоненты экранов при замене источника.

## Текущий этап: A/B/C

- Только мониторинг на синтетических данных. Не добавляй команды управления, реальный бэкенд или интеграцию с оборудованием до отдельного согласования. Старые HTML используй только как справку о функциях, не как образец дизайна.
- `monitoring-prototypes/CONTRACT.md` описывает формат демо, а не согласованный контракт API. Не считай его спецификацией интеграции.

## Мобильное приложение

- В `mobile-concepts/hybrid.html` разрешена симуляция пуска и останова цикла Н2 и настройка его расписания. Команды исполняет демоадаптер. Для подключения оборудования и команд реального API требуется отдельное согласование. Сигналы и внутренний интерфейс описаны в `mobile-concepts/PUMP-CONTROL.md`.

## Проверка изменений

- При изменениях слоя данных проверь, что тестовый источник можно заменить другим без правок UI.
- На ширине 390 px проверь оба демосценария. Различай устаревание данных и потерю связи, не показывай последнее известное состояние как текущее.
